# 四号机副本与九卡池

2026-11-25实际显卡核验：`EEC430004-5090` 对应端口25424、主机interactive46079、内部IP10.106.31.61，1张5090 32GB；`EEC430004-4090` 对应端口25005、主机interactive72412、内部IP10.106.254.57，2张4090 24GB。原别名EEC430004保留，仍指向25424。以实际GPU结果为准，用户已确认总数为9张，不是10张。

两实例共享ceg26005存储，独立部署目录为 `/opt/data/private/ECE4300-node4-api-20261125`，只准备一份模型与运行环境。`as4300` 等已有目录不改动。所有副本为同样的Qwen3-8B BF16、vLLM 0.11.0、CUDA12.8运行时、总上下文32768、max_num_seqs=8、enforce_eager；模型16文件和5.39GB环境压缩包逐一SHA256核验。GPU0端口18000，双4090的GPU1端口18001；只绑定各自内网IP并启用认证。缓存、临时文件与日志都留在独立目录。

新增API使用本次单独生成的凭据，服务器端文件权限600；网关在主服务器读取凭据，凭据不下载到本地、不提交Git。模型传输使用源IP白名单、一次性认证及固定证书的临时TLS服务，只允许指定的模型文件与运行环境包；不复制已有API服务的密钥。副本验证后关闭传输服务。

新增三个端点：

- `http://10.106.31.61:18000`：单5090。
- `http://10.106.254.57:18000`：双4090的GPU0。
- `http://10.106.254.57:18001`：双4090的GPU1。

统一九卡网关为主服务器回环地址 `http://127.0.0.1:8004/v1`，实现 `server/api_pool_gateway.py`，状态 `/health`。每次分派参考vLLM实际运行/等待请求数，以及网关自身已预留的请求和token负载；旧8003网关上尚未结束的请求同样计入实际负载。旧网关继续服务其已有题目，直到这些题目自然结束，不中断推理；新任务统一用8004。

统一队列仍使用历史状态目录 `logs/mixed-mcts-six-question-queue`，名字中的six是历史目录名，实际并发以state.json的workers为准。九卡入口：

```bash
.venv-tree-tools/bin/python -u server/run_mixed_mcts_queue.py \
  --root '/opt/data/private/ECE4300 Final Project' \
  --workers 9 --api-base http://127.0.0.1:8004/v1
```

只能启动一个调度器；旧控制器替换时只终止控制器本身，按结果文件完整路径接管现有做题进程。每个结果文件最多一个写入者。用户最终明确：先跑2.2全部27道中等评测题（原四题不重跑，余23题立即排队），再恢复2.1未完成评测。训练题生成、运行和轨迹导出已被用户暂时取消，默认training_enabled=false。原2.1在跑任务等当前API结束、保存到暂停点后退出，作为drain21占位，空位补2.2，过渡期也不超九题；最后验证全部九个active任务均为2.2。普通MCTS2.1仍暂停。各阶段生成请求额度32768，实际输出受总上下文剩余空间约束。

部署状态为主服务器 `logs/node4-provision/activation-state.json`，四号机的 `logs/provision.log`、按hostname分开的启动与API日志。清理时先移除网关后端、排空请求，再在对应节点只停止独立目录PID文件记录的本项目进程，最后删除这个独立目录；不删除其他项目目录。
